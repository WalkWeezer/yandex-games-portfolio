# Методика контроля работы 10 подагентов

Цель: гарантировать, что каждый агент доводит игру до **store-ready**, а не бросает на прототипе.  
Ты (или главный агент-оркестратор) не пишешь геймплей за них — ты **проверяешь артефакты и KPI процесса**.

---

## 1. Роли

| Роль | Кто | Что делает |
|------|-----|------------|
| Оркестратор | ты / главный чат | выдаёт промпты, принимает вехи, блокирует scope creep |
| Dev-агент ×10 | отдельные чаты | пишут только свою игру |
| QA-агент (опционально) | 11-й чат | прогоняет чеклисты по билдам |
| LiveOps позже | человек | сезоны/баланс после релиза |

---

## 2. Единый контракт артефактов (в каждой игре)

В `games/<slug>/` обязательно:

```
STATUS.md              # фаза, % готовности, блокеры, last update
STORE_CHECKLIST.md     # чеклист Яндекс Игр (ads/iap/ux)
README.md              # как запустить / собрать / опубликовать
src/                   # код
dist/                  # production build (когда готово)
DEV_MOCK.md            # как мокается SDK локально
```

Без `STATUS.md` работа агента считается невидимой = неприемлемой.

## 3. Фазы и Gate-проверки

Каждый агент проходит 6 гейтов. На следующий гейт — только после приёмки.

### Gate 0 — Bootstrap (День 1)
**Артефакты:** репозиторий/папка, Vite+Phaser стартует, пустой boot scene, STATUS заведён.  
**Проверка оркестратора:** `npm install && npm run dev` открывает canvas.

### Gate 1 — Vertical Slice (играбельное ядро)
**Артефакты:** 1 полный цикл core loop без меты.  
Примеры: 1 миссия Neon; 1 побег Работник месяца; 1 бой Море; 1 матч Легенды; merge 10 минут; 5 уровней match-3; idle 10 апгрейдов; 1 грядка+заказ; 1 волна TD; 1 runner run.  
**Проверка:** можно играть 3 минуты без консоли-ошибок.

### Gate 2 — Content Minimum
**Артефакты:** объём MVP из концепта (миссии/уровни/карты/волны).  
**Проверка:** чеклист количества контента из concept DoD.

### Gate 3 — Meta + Retention hooks
**Артефакты:** валюта, daily/цель на возврат, сохранения.  
**Проверка:** перезапуск браузера сохраняет прогресс (local + cloud API path).

### Gate 4 — Monetization SDK
**Артефакты:** interstitial, rewarded, ≥1–2 IAP, consume/restore purchases.  
**Проверка по чеклисту Яндекса:**
- RV только по кнопке с текстом награды
- нет рекламы mid-action
- пауза звука/геймплея на ads
- IAP цены с валютой портала
- необработанные покупки проверяются на старте

### Gate 5 — Store Ready
**Артефакты:** `dist/`, иконки/обложка placeholders, STORE_CHECKLIST 100%, туториал, desktop+mobile.  
**Проверка:** 30-минутный smoke: туториал → прогресс → смерть/поражение → RV → покупка (mock) → лидерборд.

## 4. Ритм контроля (ежедневный)

### Standup-формат (агент пишет в STATUS.md)

```md
## Date
- Phase: Gate X
- Done since last:
- Evidence: (ссылки на сцены/файлы/скрины)
- Blockers:
- Next 24h:
- Risks (scope/tech/balance):
```

### Оркестратор отвечает только одним из трёх

1. **ACCEPT** — гейт пройден, можно дальше.  
2. **REWORK** — список дефектов (макс 5 пунктов, приоритет).  
3. **CUT SCOPE** — что вырезать, чтобы успеть в стор.

Запрещено: «продолжай в том же духе» без приёмки гейта.

## 5. Как оркестратор реально «гарантирует» результат

Гарантия = процесс, не магия. Рабочая схема:

### A. Один агент = одна игра = один DoD
Промпт уже содержит DoD. Оркестратор не принимает «почти готово».

### B. Timebox на гейты
Пример P0-игры (Работник месяца/Курьер/Idle/Merge/Match-3):

| Gate | Бюджет |
|------|--------|
| 0 | 0.5 дня |
| 1 | 2–3 дня |
| 2 | 3–5 дней |
| 3 | 1–2 дня |
| 4 | 2 дня |
| 5 | 2 дня |

Если срыв >40% бюджета гейта → **CUT SCOPE**, не «ещё полировка».

### C. Definition of Ready для приёмки
Оркестратор сам (или QA-агент) запускает билд и проходит smoke-скрипт:

```text
SMOKE:
1. Cold start < 5s до меню
2. Tutorial completable
3. Core loop x3
4. Kill tab / reopen → save ok
5. Trigger rewarded path
6. Trigger interstitial path
7. Open shop / mock purchase
8. No red console errors
```

### D. Красные флаги (агента останавливаем)

- Переписывает движок после Gate 1  
- Добавляет мультиплеер/бэкенд без запроса  
- Нет STATUS >48 часов  
- Реклама в середине экшена  
- «Сначала идеальный арт, потом геймплей»  
- Ломает чужие папки

### E. Эскалация

1. REWORK (1 итерация)  
2. CUT SCOPE  
3. Перезапуск агента с тем же промптом + списком «уже сделано / не трогать»  
4. Человек дожимает Gate 5

## 7. Промпт оркестратора (для главного чата)

```text
Ты — оркестратор портфеля из 10 игр для Яндекс Игр.
Не пиши геймплей за подагентов. Твоя работа:
1) Читать STATUS.md и STORE_CHECKLIST.md каждой игры
2) Принимать/отклонять Gate 0–5 по docs/agents/control-methodology.md
3) Резать скоуп, если срывается timebox
4) Держать PORTFOLIO_BOARD.md актуальным
5) Разрешать конфликты SDK/общих утилит централизованно в packages/yg-sdk-wrapper (если появится)

Сейчас проверь игру: <slug>
Верни: ACCEPT / REWORK / CUT SCOPE + конкретный список.
```

## 8. Общий SDK-wrapper (рекомендуется после Wave 1)

После 2–3 игр вынеси в `packages/yg-sdk-wrapper`:
- `showFullscreen()`
- `showRewarded(): Promise<boolean>`
- `payments.buy()`
- `cloud.save/load`
- `leaderboard.set/get`
- `DEV_MOCK` автоматический вне окружения Яндекса

Это снижает риск, что 10 агентов криво интегрируют SDK 10 раз.

---

## 9. Критерий успеха портфеля

Портфель успешен, если:
1. ≥8/10 игр прошли Gate 5 и загружены в консоль Яндекса.  
2. ≥5/10 прошли модерацию с первой-второй попытки.  
3. ≥3/10 показывают D1≥25% на первой тысяче игроков.  
4. Хотя бы 1 midcore (Neon / Море / Легенды / Автобашни) даёт устойчивый IAP.

Контроль агентов заточен не под «красивый код», а под **эту воронку**.
