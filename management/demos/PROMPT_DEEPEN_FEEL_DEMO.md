## МЕТОД УГЛУБЛЕНИЯ (порядок слоёв)

Работай **строго по слоям**. Не прыгай к мета/wireframe, пока слой 1–3 не ощущается.

### Слой 0 — Инвентаризация (1 проход)

- Прочитай текущую демку и DESIGN (Pass-2 / feel targets).
- Коротко выпиши: что уже есть, что врёт дизайну, что ломает feel.
- Если демка расходится с Pass-2 — сначала выровняй вектор, потом контент.

### Слой 1 — Читаемый core loop

Цель: за 5–10 секунд понятно «что делать / как проиграть / как выиграть».

- Движение игрока: один ясный verb (шаг / свайп / тап) — без скрытого автобега, если это не задумано.
- Препятствия/коллизии честные.
- Fail и win считываются с HUD/копирайта.
- Длина рана подогнана под playtest (часто 30–60с), не «вечность».

### Слой 2 — Угрозы как роли (паттерны), не как скины

- Каждый тип врага = **читаемый паттерн поведения**, не только цвет.
- Разлок по прогрессии: сначала 1 простой тип → постепенно новые.
- Исключения разлока допустимы (пример: «директор с 3 этажа», остальные каждые N).
- Ограничение одновременности: лимит мобов на поле; часто «макс. 1 экземпляр типа», кроме специально разрешённых (пример: HR и клиенты-клещи).
- **Все мобы двигаются плавно** (интерполяция/`frac`), без телепортов по клеткам. Рывки = быстрый smooth dash, не blink-телепорт.

### Слой 3 — Кривая сложности (внутри рана + между ранами)

Раздели два ускорения:

1. **Внутри рана (фазы дня/волны):** прогрессия есть, но **потолок ускорения умеренный** (ориентир ≤ +25% к старту рана). Без скрытого «разгона до ×2.5».
2. **Между ранами (этаж/уровень):** медленный рост (ориентир **+1%/этаж**, не +5%), иначе к mid-game всё нечитаемо.
3. **Лимит одновременных угроз:** база N, +1 редко (например каждые 15 этажей), не каждые 5.
4. **Пространство:** раскладка препятствий меняется с прогрессом; опционально рост поля каждые K этапов (+1 col/row по очереди).

### Слой 4 — Бонусы / гаджеты (fantasy, не статы)

- 1–2 бонуса с ясным правилом (slow-mo, 1 hit shield, …).
- Обыграй фантазию игры: не «сорвать с NPC», а например **предмет падает → подобрать с пола**.
- Индикация на игроке и в HUD обязательна.

### Слой 5 — Dev-инструменты playtest

Минимум:

- God-mode / бессмертие.
- Счётчик «смертей» в god-mode: **сколько раз и на каком этапе** «убило бы».
- Старт всегда с этапа 1 в нормальном режиме; **dev-выбор стартового этапа**.
- После смерти в нормальном режиме — возврат к стартовому этапу (или по правилам меты — см. слой 7).

### Слой 6 — Wireframe UI (отдельная вкладка)

- Добавь вкладку **Wireframe UI** на страницу проекта (не смешивать с canvas-демкой).
- Простые dashed-блоки, portrait 360×640, список экранов.
- Экраны минимум: Boot, Menu, Hub, Run HUD, Pause, Fail/Revive, Result, Shop, Daily (если есть в дизайне).
- Сначала сверка иерархии/CTA, потом детализация.

### Слой 7 — Мета-решения (зафиксировать в DESIGN + wireframe)

Ответь явно и отрази в UI:

1. **Прогресс этапов:** сохранять max unlock + выбор этапа в хабе (не «всегда с 1» в проде). Демка может стартовать с 1, но wireframe/хаб показывает сейв.
2. **Daily:** не модалка перед каждым этажом. Вход с **Хаба** → экран **Daily select** (1/день, правило, награда, старт / назад).
3. Смерть ≠ сброс всего прогресса; смерть = конец рана.

Обнови feel targets / Pass-2 в `DESIGN.md` коротко, без простыни.

## ПРАВИЛА ИТЕРАЦИЙ С ПОЛЬЗОВАТЕЛЕМ

- Одна тема за раз, если пользователь не просит пачку.
- После правки: 2–5 строк «что изменилось + как проверить» (hard refresh → Демка / Wireframe).
- Числа сложности называй явно («+1%/этаж», «макс +25% за день», «лимит 3 моба»).
- Если пользователь жалуется на темп/читаемость — сначала режь скорость и плотность, не добавляй контент.

- [ ] Ускорение рана и мета-ускорение разделены и ограничены  
- [ ] Движение угроз плавное  
- [ ] 1–2 бонуса с фантазией игры  
- [ ] Dev: god + счётчик смертей + старт-этап  
- [ ] Вкладка Wireframe UI с хабом и (если нужно) Daily select  
- [ ] DESIGN feel targets обновлены под факт демки
