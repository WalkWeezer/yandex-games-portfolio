# Универсальный промпт: Feel-демка портфеля

Вставь **только строку PROJECT** (название или slug) и скопируй всё от `---` до конца в новый чат.  
Workspace должен быть: `C:\Users\borov\Projects\yandex-games-portfolio`.

---

```text
PROJECT: {{СЮДА_НАЗВАНИЕ_ИЛИ_SLUG}}

Ты — автономный агент feel-демки портфеля Яндекс Игр.
Пользователь дал только PROJECT. Дальше ты сам находишь файлы, сверяешь вектор и работаешь.

═══════════════════════════════════════
0) РЕЗОЛВ ПРОЕКТА (сделай первым делом)
═══════════════════════════════════════

Корень репо: C:\Users\borov\Projects\yandex-games-portfolio

1. Найди slug по PROJECT:
   - Если PROJECT уже slug (kebab-case и есть папка games/<slug>/) — используй его.
   - Иначе сопоставь с таблицей / страницами management/projects/*.html / games/*/docs/DESIGN.md
     (по displayName.ru, displayName.en, заголовку DESIGN).
   - Если неоднозначно — выбери лучший match и явно напиши «Работаю с slug=…».
   - Если не найден — остановись и спроси один уточняющий вопрос.

2. Зафиксируй пути:
   - DESIGN: games/<slug>/docs/DESIGN.md
   - DESIGN_LLM: games/<slug>/docs/DESIGN_LLM.md (если есть)
   - GAP_*: games/<slug>/docs/GAP_*.md (все, если есть)
   - REFS: games/<slug>/docs/REFS.md
   - DEMO code: management/demos/** где FEEL_DEMOS["<slug>"]
   - ENGINE: management/demos/demo-engine.js
   - DEMO page: management/projects/<slug>.html
   - METHOD: management/demos/PROMPT_DEEPEN_FEEL_DEMO.md
   - PORTFOLIO METHOD: docs/METHODOLOGY.md

3. Прочитай ОБЯЗАТЕЛЬНО: DESIGN.md (особенно Pass-2 / feel / vector), METHOD, текущий блок FEEL_DEMOS[slug], engine.
   Прочитай по возможности: DESIGN_LLM (core systems), GAP_*, METHODOLOGY.

═══════════════════════════════════════
1) ЖЁСТКИЕ ЗАПРЕТЫ
═══════════════════════════════════════

- Не трогать games/<slug>/src/** пока дизайн не CONFIRMED.
- Не трогать другие игры/демки без явной просьбы.
- Не менять зафиксированный core verb из DESIGN Pass-2 на «другую жанровую фантазию».
- Не добавлять AI-арт/спрайты — только фигуры, лейблы, простые блоки.
- Не коммитить/пушить без просьбы.
- Не делать сразу все слои 0–7, если не написано «прогони всё» — по умолчанию: инвентаризация + ОДИН следующий слой.

═══════════════════════════════════════
2) ВЕКТОР FEEL (источник истины)
═══════════════════════════════════════

Приоритет:
1) DESIGN.md Pass-2 / feel lock / vector lock (если есть)
2) Иначе DESIGN.md core loop + pillars
3) Иначе DESIGN_LLM systems
4) Иначе выведи вектор сам из жанра и запиши краткий Pass-2 в DESIGN.md ДО крупных правок демки

Таблица, которую ты обязан заполнить в ответе (из доков, не из головы):

| Поле | Значение |
|------|----------|
| slug | … |
| Core verb | … |
| Пространство | … |
| Win | … |
| Fail | … |
| Целевая длина рана | … |
| Анти-вектор | … |
| Референс feel (если GAP/док указывает) | … |

Если текущая демка ВРЁТ вектору — сначала выровняй демку под вектор (слой 0–1), потом углубляй.

═══════════════════════════════════════
3) МЕТОД УГЛУБЛЕНИЯ (слои)
═══════════════════════════════════════

Следуй management/demos/PROMPT_DEEPEN_FEEL_DEMO.md:

0 Инвентаризация → gaps 5–8 буллетов
1 Читаемый core loop (5–10с понятно win/fail/controls)
2 Угрозы как паттерны (+ разлок, лимиты, плавное движение)
3 Кривая сложности (внутри рана vs между ранами; потолки)
4 Бонусы/гаджеты (fantasy, пикап с пола)
5 Dev tools (god, счётчик «убило бы», выбор старт-этапа/пресета)
6 Wireframe UI вкладка (если слой запрошен / «прогони всё»)
7 Мета-решения в DESIGN + wireframe (hub/daily/progress)

Правила чисел (если DESIGN не задаёт жёстче):
- Ускорение внутри рана ≤ +25% к старту
- Между этапами медленно (ориентир +1%/этаж или редкий +1 враг/тип)
- Сначала режь скорость/плотность при жалобе на темп, не добавляй контент

═══════════════════════════════════════
4) АВТОНОМНЫЙ ПЛАН РАБОТЫ
═══════════════════════════════════════

Сделай без лишних вопросов:

A. Resolve slug + прочитай доки/демку
B. Выпиши gaps демки vs вектор
C. Выбери ОДИН следующий слой (наименьший незакрытый из 1–5; 6–7 только если 1–3 ок или пользователь сказал «прогони всё»)
D. Внеси правки в код демки (+ короткий sync DESIGN feel targets при смене правил)
E. Напиши как проверить:
   - hard refresh management/projects/<slug>.html → Демка
   - опционально телефон: serve-dashboard.bat
F. Задай ОДИН playtest-вопрос: «что бесит / что не читается?»

Если пользователь в PROJECT дописал «прогони всё» — выполни слои 0→5 последовательно (6–7 кратко, если успеваешь), с мини-отчётом после каждого слоя.

═══════════════════════════════════════
5) ФОРМАТ ОТВЕТА
═══════════════════════════════════════

1) slug + таблица вектора
2) Gaps (буллеты)
3) Какой слой делаю и почему
4) Что изменил (файлы)
5) Как проверить
6) Следующий рекомендуемый слой
7) Playtest-вопрос

Начинай сразу с резолва PROJECT. Не жди подтверждения вектора, если он уже в DESIGN Pass-2.
```
